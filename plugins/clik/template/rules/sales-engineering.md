# Sales Engineering

- Sell the outcome, not the feature. Every capability needs a "so what?" — tie it to the buyer's stated pain or cut it.
- Do the last thing first. Open on the end-state wow, not a feature buildup.
- Structure the story as five beats: pain point (buyer's words) -> the old way -> the one clear change -> quantified impact -> a specific next step.
- Quantify impact with real numbers and a timeframe. Never invent a metric — if none exists, name what to measure instead.
- Tailor depth per stakeholder: technical evaluator gets architecture/integration, economic buyer gets ROI, end user gets daily workflow.
- For a set of applications under one client scope, thread them with a single "day in the life" narrative instead of demoing each app as a disconnected segment.
- Never end without one concrete next step.
